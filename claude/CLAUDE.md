# Conventions

## プロジェクト横断参照

開発は `~/src`、資料（スライド・会議録・抄録・講義）は `~/Documents` にあり、
同じ案件が両方に散らばっている。名前が出たら以下で実体を解決すること。

実体は3箇所に分かれている:
- `~/src` … コード（ghq レイアウト `~/src/github.com/<org>/<repo>`）
- `~/Sync/Projects` … データ・実験成果物
- `~/Documents` … 資料（スライド・会議録・抄録・講義）

解決手順:
1. **`~/.claude/project-mapping.md` を最初に引く。** 載っていればそのパスを使う。
2. 載っていなければ 3箇所を検索して実体を特定する（`rg -il '<名前>' ~/Documents` 等）。
   ただし `vision` `app` `tools` `chat` `VLM` `tt` のような一般語は grep が誤爆するので、
   ヒットを鵜呑みにせず中身を確認する。
3. **どの場合も推測でパスを書かない。** 実装の話は解決したパスの実コードを読んでから答える。

@~/.claude/project-mapping.md

## `,` 始まりのディレクトリ（プロジェクトごとのメモ置き場）

各プロジェクトの root にある `,` 始まりのディレクトリは、私(ken)個人の作業スペース。
global gitignore (`,*/`) で ignore 済み。Claude Code はこれらを前提として把握しておくこと。

- `,` … ちょっとした ignore の書き捨てスクリプトやチェック用ファイルの置き場（throwaway/scratch）
- `,links` … 他プロジェクトへのシンボリックリンク。**全プロジェクトには張っていない**ので、
  無いことを「関連が無い」と解釈しないこと（横断参照の主手段は上記の検索）
- `,docs` … メモ・ドキュメント置き場

活用方針:
- `,links` の中身は他プロジェクトの参照なので、書き方や実装パターンを調べる材料として読んでよい
- `,` 配下は書き捨て前提。ここのスクリプトやメモを正式な成果物と混同しない
- これらを git にコミットしない（ignore 済み）
